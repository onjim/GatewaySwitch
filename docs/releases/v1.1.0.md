# v1.1.0 - 默认路由重复检查与稳定修复

## 主要修复

- 针对 Wi-Fi 网络重新下发路由后，竞争默认路由重新出现或目标路由度量值变化的情况，加强默认路由守护。先确保目标路由存在，再清理受管网卡上的竞争默认路由，并将目标路由的 RouteMetric 恢复为 0。
- 在原有后台轮询守护基础上，每轮修复最多尝试 3 次；每次修复后间隔 400 毫秒连续观察 3 次，确认路由稳定后再完成校验。校验期间再次发现路由冲突时继续尝试。
- 网络身份变化、权限错误或未伴随路由冲突的 DNS 校验错误会停止重试；原始备份保留，不会因路由修复被覆盖。
- 增加修复前后路由快照及错误日志，保存在 `%LOCALAPPDATA%\GatewaySwitch\gateway.log`，达到约 1 MiB 时轮转并保留上一份日志。

## 恢复可靠性

- 按 IPv4 / IPv6 地址族对应的 DNS 配置对象写入和重置 DNS。
- 先恢复 DNS，再处理路由，降低路由删除失败时仍残留旁路由 DNS 的风险。
- 清理旧备份中混入的旁路由 DNS，恢复 IPv6 链路本地路由时不沿用过期的接口 scope。

## 验证与限制

- 新增模拟回归覆盖瞬时与校验期间的路由重注入、持续冲突重试上限、网络变化及权限 / DNS 错误中止，以及 DNS 和 IPv6 路由恢复。
- 这是轮询与有界重试，不保证路由重新下发后完全没有短暂流量绕行；也不调整其他网卡的接口优先级或 VPN 更具体的路由。
- 代码和模拟测试验证的是竞争默认路由与目标路由度量值漂移的处理，不能单凭这些确认某次现场故障必然由 Wi-Fi 下发造成。实际 DHCP 续租、IPv6 路由重新下发及睡眠唤醒仍需测试网络验证。
